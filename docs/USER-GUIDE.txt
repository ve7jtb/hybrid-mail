HYBRID MAIL — LOCAL DEVELOPMENT APP

Launch
  Run ./run.sh after building, or open dist/PQ Mail.app after packaging.
  The packaged app includes Java, OpenSSL and the built PKCS#11 modules.
  It is ad-hoc signed for local testing, not notarized. Python 3 must be installed.
  See docs/DESKTOP.md for saved identities, inbox and Google OAuth setup.

Implemented profiles
  Pure signature: ML-DSA-65
  Composite signatures: MLDSA65-ECDSA-P256-SHA512 and MLDSA65-RSA3072-PSS-SHA512
  Pure encryption KEM: ML-KEM-768
  Composite encryption KEM: MLKEM768-ECDH-P256-SHA3-256
  CMS KEMRecipientInfo: HKDF-SHA256 + AES-256 key wrap
  Content encryption: AES-256-GCM, S/MIME AuthEnvelopedData
  Opaque S/MIME SignedData with signed attributes, then optional encryption.
  Signing and encryption profiles are independent; all four combinations tested.
  Composite encodings/OIDs are those implemented by the pinned BC snapshot below.

Try without a server
  1. Keys → Create identity. Create Alice and Bob identities with their
     email addresses and unique .p12 filenames. Choose Pure or Hybrid for each.
  2. With Alice loaded, export her signing certificate. With Bob loaded, export
     his encryption certificate. Choose .cer for DER or .pem for PEM; both contain public certificates.
  3. Load Alice. Import Bob's encryption certificate. Confirm its fingerprint
     with Bob. Compose with matching From and To, then Save signed .eml.
  4. Load Bob. Pin Alice's signing certificate after confirming its fingerprint.
     Read & verify → Open .eml. The app authenticates/decrypts, checks the
     signature, and distinguishes pinned versus untrusted signing certificates.
  You can also send to yourself using one identity and its encryption certificate.
  Signing-only is the default; optionally enable encryption for the recipient.
  Manage saved signing/encryption contacts in the Certificates tab.
  Export destinations are never overwritten.

Mail transport
  SMTP: authenticated submission with required STARTTLS, default port 587.
  IMAP: TLS, default port 993; lists ten newest INBOX arrivals read-only.
  Double-click a row to fetch its body; refresh updates headers.
  Server hostname checks and connection/read/write timeouts are enabled.
  Host, port and username are saved; account passwords are not saved.
  Google OAuth and IMAP inbox listing were observed with a live account.
  Live SMTP delivery has not been independently verified. Password and Google Desktop OAuth
  authentication are supported. SMTP implicit TLS/465 is not offered.

Scope and trust
  This is an experimental development app. One To recipient; no mailbox sync.
  Desktop supports safe local HTML reading and simple Compose formatting.
  Images/active content are blocked; website links require confirmation.
  Formatted mail includes signed text/HTML alternatives; file attachments use S/MIME.
  20 MiB message limit. Only the two profiles above are selectable for sending.
  Reader handles opaque or multipart signed text/plain content, optionally inside
  AuthEnvelopedData. Ordinary text mail is labelled unsigned; legacy EnvelopedData is unsupported.
  Self-issued test certificates are generated for the two key roles, valid one year.
  Trust uses exact signing-certificate pinning; no CA path building, OCSP or CRLs.
  Certificate validity and key usage are checked. rfc822Name SAN binds addresses.
  Outer From/To/Subject headers remain unsigned and unencrypted; the reader flags
  a From/certificate mismatch. A valid signature is not automatically trusted.
  Software identities retain encrypted PKCS#12 files with owner-only permissions.
  Token identities store only public certificates. Identities, pins and token
  configuration persist in Application Support. Both components of hybrid
  signing and decryption can use the YubiKey through PKCS#11. PINs are temporary.
  Google OAuth tokens remain in memory until sign-out/exit or expiry.
  No third-party S/MIME client interoperability or production security audit yet.

YubiKey / external mu
  See docs/EXTERNAL-MU.txt. Both signature profiles have a tested external-mu backend.
  TestMuAdapter is SOFTWARE ONLY. adapters/ykman-mu.py is the Beta0 CLI bridge.
  The public Yubico PIV SDK documentation supplied by the user was reviewed on
  2026-11-16; it does not document ML-DSA or an external-mu operation. The installed
  ykman 6.0.0-beta.0 provides --mu; the new adapter uses that interface.

Build and test
  See README.md for JDK/Maven prerequisites and dependency setup.
  ./scripts/build-dependencies.sh
  ./build.sh test
  ./scripts/build-pkcs11.sh
  ./package.sh
  Tests use ephemeral local identities and delete their keys afterward.
  docs/TEST-RESULTS.txt records the run. Tests do not connect to a mail server.

Beta0 hardware signing
  The desktop app uses its bundled PKCS#11 backend automatically for saved
  YubiKey identities selected under Keys. The legacy ykman adapter is available
  through the Terminal test launcher; its PIN/touch prompts appear in Terminal.
  scripts/test-beta0.sh creates local test certificates and verifies pure/hybrid
  signed .eml messages, then opens the UI with the pure token identity loaded.
  No token provisioning and no mail sending occur. See README.md for commands.
